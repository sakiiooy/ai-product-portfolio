# 同花顺·事件透镜：投资事件情报与证据时间线

产品设计 v1.0｜2026-11-19

本方案面向同花顺的投资者使用场景。交付范围为产品设计与合成事件交互演示；演示不接入实时金融数据，不代表已实现线上监控或完成公开部署。附件中的比赛时间和实现交付项用于估算落地范围。

## 1. 产品定位与优先用户

**让用户在一分钟内看清：一件事从哪里来、到底变了什么、现在有哪些依据、与自选股有什么关系。**

产品围绕“事件—主张—证据—结论版本”组织信息。同一事件的十篇转载只增加传播记录；一份更正公告可能改变整个当前快照。

优先用户是关注少量自选股、每天反复核对公告与消息的个人投资者。研究员作为次级用户，使用来源核查、历史回放与证据导出。这里是待验证的用户假设，并非已有访谈结论。

核心任务：当用户看到“某公司签下大单”的消息时，能迅速判断它是原始披露、独立核实、条件性分析还是同源转述，并知道后续发生了哪些修正。

价值验证以“正确理解状态、找到原始依据、识别不确定性”衡量。产品输出事实与关系解释，不将事件强弱转换成买卖建议或确定性价格预测。

## 2. 三步主链路

### 第一步：从自选股发现实质变化

入口放在自选列表的“事件更新”与个股资讯页的“追踪此事”。允许从新闻链接或粘贴文本创建事件候选。

事件收件箱以事件为一行，展示：事件名、直接关联标的、当前进程、本次变化、关键未确认项、最后成功检查时间。优先展示否认、更正、终止、关键冲突与直接当事方变化；仅转载不提醒。排序规则可解释，不按报道数量推断真实性。

示例通知：“合作框架上限由披露的10亿元更正为1亿元；仍无最低采购承诺。查看更正原文。”

### 第二步：先读当前快照，再看变化

详情页首屏固定回答五个问题：

| 用户问题 | 展示与动作 |
|---|---|
| 最早从哪里来？ | “已收录范围内最早披露”与“已核实原始出处”分别显示；点击展开转引链 |
| 事实变了什么？ | 金额、参与方、阶段、条件等字段的前后差异；逐项引用原文 |
| 哪里有冲突？ | 对同一主张并列显示支持、反对、限定与待核实证据 |
| 现在是什么状态？ | 事件进程、主张证据状态、资料新鲜度分别呈现；注明截至时点 |
| 与我关注的标的有什么关系？ | 直接角色、经证实的关系链、AI提出的潜在关联分层显示 |

快照采用“已获得支持／存在争议／尚不清楚”三段简短文本。每句附证据编号。读者不必先浏览一篇长摘要才能发现关键缺口。

### 第三步：核查并持续追踪

点击证据编号打开侧栏：原始文档、精确片段、页码或段落、四类时间、来源独立性、历史版本与采用理由。无原文权限时展示限制，保留可访问元信息，不能把AI解读冒充原文。

用户可以订阅实质变化、回到历史时点、反馈错误合并。个人拆分即时影响自己的视图；涉及全局事件的拆分进入复核，不允许单个用户改写公共事实。所有操作可撤销。

## 3. 信息架构与关键交互

只设三个主要页面：

1. **事件收件箱**：我的关注、实质变化、待核实、已归档。
2. **事件详情**：当前快照 → 变化时间线 → 主张与冲突 → 标的关系。
3. **证据侧栏**：原文定位、来源链、时间、版本与可用性。

核心交互包括：

- **只看变化**：把更正、否认、新事实与重复传播分开；转载默认折叠并显示“同源转引12篇”。
- **回到当时**：切换到某个系统时点，还原当时已收录的材料与结论；未来材料不可见。
- **冲突对照**：把“已签正式合同”拆为可核查主张，突出两份材料的主体、对象、时点和措辞差异；不同口径不强制判为冲突。
- **为什么关联我**：展开具体关系与证据。供应商关系不能直接推出获得本次订单。
- **纠正这次合并**：展示合并理由及受影响材料；拆分后重算摘要、来源链、冲突、关系与通知，保留审计记录。

## 4. 核心数据模型

| 对象 | 核心字段与意义 |
|---|---|
| Event 事件 | 内部稳定ID、标准主体、事件类型、对象/交易对手、业务编号、时间范围、父子事件关系、合并与拆分历史 |
| SourceDocument 来源材料 | 提供方、原始URL/公告编号、来源类型、原文权限、获取状态、来源家族ID |
| DocumentVersion 文档版本 | 内容指纹、版本号、原文存储引用、四类时间、取代关系；旧版本不覆盖 |
| Claim 主张 | 主体、谓词、对象、金额/单位/币种、范围、适用时点、条件、内容性质、原文定位 |
| EvidenceLink 证据关系 | 文档版本到主张的“支持/反对/限定/引用/更正/撤回”，以及独立性与适用范围 |
| EventSnapshot 结论版本 | 事件进程、各主张状态、尚待核实项、有效证据ID、规则与模型版本、系统生成时间 |
| TargetRelation 标的关系 | 标的ID、角色、关系路径、逐段证据、有效期、事实/推断标签 |

同一文档可以包含多种主张。事实陈述是一种内容性质，“已获得核验支持”是另一维度，不能将可核查陈述直接等同于事实成立。

## 5. 事件识别、合并与溯源

处理顺序：实体消歧 → 事件候选召回 → 结构化要素比对 → 合并决策 → 主张对齐 → 版本重算。

召回可以使用文本向量、股票代码、关键词与时间窗口。正式合并需要比较标准主体、事件对象、交易对手、事件类型、交易/项目编号与阶段连续性。上游的same_events或相似度仅作为候选线索。

自动合并优先依赖强标识，如同一公告明确引用的交易编号。只有标题相似、同一公司或同一月份时，不自动合并。无强标识的阈值必须用标注集校准；低把握进入“疑似同一事件”。

合并边界：

- 同一交易的传闻、筹划、签署与终止可归入一个事件，保留不同主张。
- 同一公司同月的两笔交易应拆开。
- 框架协议、正式订单、交付和收入确认具有阶段关系，不能互相替代。
- 将不同项目合并后产生的冲突不能用“双方口径不一致”掩盖，应先检查是否误合并。

溯源区分两个答案：“系统当前找到最早的公开披露”和“已核实的原始出处”。显示检索来源范围、时间覆盖与缺口。匿名截图无可验证出处时，显示“原始出处未核实”，不宣称全网首发。

对转载建立有向引用关系与来源家族。同一原帖被转述12次，仍是1个来源家族。若依赖关系不明，不默认其独立；计为“独立性未核实”。

## 6. 内容性质与证据权重

| 内容性质 | 示例 | 展示方式 |
|---|---|---|
| 可核查陈述 | “截至11月2日未签署正式合同” | 保留发言者、范围和时点，再标核验状态 |
| 观点 | “该合作具有战略意义” | 观点归属与发表时间，不进入已发生事实 |
| 条件推测 | “若量产成功，收入可能增长” | 条件、推导链与未证实环节显式展示 |
| 传闻 | 匿名账号称“已签20亿元订单” | 原始出处、转载家族、待核实主张；不升级为事实 |

证据价值按“对这项主张能说明什么”判断：材料是否原始、是否有权就该事项表态、是否直接涉及主张、可否定位原文、是否独立、适用范围与时间是否一致。

UI给出“直接原始材料／独立核实材料／转引材料／出处未核实”等标签与采用理由，不将证据压成一个看似精确的总可信度。

关键规则：

- 公司公告可有力证明其公开披露了什么；管理层预期仍是预期，公司否认也保留表态归属。
- 更新较晚不能单凭时间覆盖较早的直接证据。明确更正才取代同一字段；新时点事实则是状态演变。
- 两个独立直接来源在同一对象、时点、口径上矛盾时，保留双方并显示“待核实”。
- 转载数量、阅读量、股价变化不用于证明事件真实。
- 原始字段、文本提取值和模型解释分别存储，摘要不得循环引用自己作为证据。

## 7. 时间语义与历史回放

每条材料保存四类时间，并同时保存来源原始字符串、解析时区、精度与解析状态：

| 时间 | 含义 | 不能替代什么 |
|---|---|---|
| 事件发生时间 | 签署、会议、交付等实际发生时间，可为区间或未知 | 不用披露时间自动补全 |
| 首次披露时间 | 来源第一次公开该版本信息的时间 | 不用抓取时间冒充首发时间 |
| 系统抓取时间 | 本系统第一次获得该版本的时间 | 不冒充上游create_time |
| 来源更新时间 | 来源明确给出的修改时间，未知则留空 | 不用本系统重算时间补全 |

另外记录系统结论生成时间。只有日期的材料按“日”展示，不编造00:00的精度；相对时间按来源时区解析，无法确定时显示缺失。

默认按披露时间浏览，支持事件发生时间视角。历史查询严格分为：

1. **系统当时已知**：只使用在所选时点之前已抓取且已公开的文档版本，显示当时保存的结论。
2. **按披露时点回看**：使用今天已收录的资料复原当时公开信息，迟到材料明确标记“后来补录”；不冒充系统当时已知。

迟到公告可以插入披露时间线，但不能改写已保存的历史快照。精确回放还需固定当时规则与模型版本。

## 8. 三组状态与更新规则

### 事件进程

传闻线索、筹划/接洽、框架协议、正式签署、审批、履行、完成、终止。每类事件按模板配置合法阶段与跳转；无法判断则“进程待确认”。

### 主张证据状态

待核实、已获得支持、存在冲突、当事方否认、已更正、已撤回、依据不再适用。一个事件内多项主张可以具有不同状态。

### 资料新鲜度与可用性

最近检查成功、超过复核周期、接口异常、原文不可访问、正文缺失。资料状态不自动改变事件真伪；界面显示最后一次成功核验与尚未覆盖的时间段。

| 触发 | 对当前结论的改变 |
|---|---|
| 新增独立、直接证据 | 更新对应主张；有实质增量才通知 |
| 否认 | 标记具体被否认主张及范围，不扩大为“整件事虚假” |
| 明确更正 | 对应字段旧版失效；摘要、派生计算、标的关系、缓存与通知同步重算 |
| 撤稿/撤回 | 文档保留记录，撤回其当前支撑作用；若缺少其他依据则降为待核实 |
| 明确终止 | 更新被终止事项，不自动推定其他合同、订单或交易同时取消 |
| 依据失效/逾期 | 将依赖它的现时判断标为需复核；保留历史事实与历史证据 |
| 抓取失败 | 保留最后已知快照并显著标旧；停止生成新的肯定结论，成功恢复后补录与去重 |

例：意向协议到期但无续签资料，显示“原协议有效期已届满，后续安排待核实”；不写“公司不再合作”。

## 9. 与关注标的的关系

关系分为三个层次：

1. **直接参与**：收购方、出售方、合作方、监管对象等，附直接文档证据。
2. **经核实的间接关系**：股权、客户、供应商等，逐段列出关系与有效时间；是否参与本次事件需另有证据。
3. **潜在关联**：行业重叠或AI推断的业务传导，显式标为假设，不混入直接标的列表。

例：一份年报可支持“示例丙公司过去是甲公司的供应商”，不能支持“丙获得了本次合作订单”。上游合作终止后，相关传导假设应失效或回到待核实；供应商历史关系本身不因此被抹去。

关系强弱与事件材料权重分开，不将它们换算成“利好程度”或收益分数。若展示行情，只标注有依据的事件时点与市场数据时点，不写“该消息导致上涨”。

## 10. 合成案例：从传闻到终止

以下公司、资料、金额与日期全部为合成演示，不对应真实证券；时间为北京时间（UTC+8）。

| 披露时点 | 新材料 | 当前应显示 | 必须保留的缺口 |
|---|---|---|---|
| 11/02 09:10 | 匿名账号称甲乙“已签20亿元供货订单”，随后12篇同源转载 | 已出现传闻；原始账号身份未核实；1个来源家族 | 是否接洽、签约、金额均未核实 |
| 11/02 11:10 | 甲回应：截至回应时未签正式供货合同 | “已签正式合同”主张遭当事方否认 | 不能据此认定从未接触；匿名消息不能整体判假 |
| 11/02 13:00 | 研报称“若合作落地，或增加收入” | 条件推测，未增加订单事实 | 合作、执行、收入确认条件均需补证 |
| 11/03 18:00 | 公告披露框架合作，拟合作上限10亿元，无最低采购承诺 | 框架已披露；上限10亿元；正式订单待核实 | 上限不是订单或收入；与昨日回应不构成同一时点冲突 |
| 11/04 09:00 | 更正公告：上限应为1亿元 | 当前上限1亿元，旧披露10亿元已更正 | 是披露修正，不能写成“订单缩水90%” |
| 11/05 18:00 | 公告披露框架终止 | 该框架终止；金额仅作历史条件展示 | 未披露订单、交付或收入，不能推定取消已生效订单 |

演示还应允许模拟资料超过复核周期与来源异常，证明这两种情况不会让历史框架自动“复活”，也不会创造新的终止事实。

## 11. AI、规则与人的分工

AI处理非结构化语言：实体消歧候选、主张与条件抽取、来源引用识别、事件匹配建议、冲突候选、带引用的变化摘要与关系解释。

规则引擎负责：单位与币种校验、时点过滤、版本取代、更正与撤回传播、来源家族去重、状态约束、引用完整性、访问权限与审计。数值差异先检查“上限/承诺/实际”“含税/未税”“集团/上市主体”等口径，再判冲突。

人工重点复核错误合并、强证据冲突、来源不明但传播广的高影响消息。系统不具备完整原文时，允许输出“证据不足”，不强制给出单一结论。

实现可采用：接入适配层 → 不可覆盖的材料版本库 → AI结构化抽取 → 校验与事件匹配 → 证据关系与状态计算 → 带引用快照 → 订阅与前端。MVP用关系数据库保存证据边即可，不必先引入图数据库。

每项AI输出要求返回引用的document_version_id、原文位置、内容性质、条件与缺失项。没有可定位依据的候选不进入“已获得支持”。新材料重算后运行引用检查和旧版本失效检查，再发布快照。

外部材料中的指令均按内容处理，不执行其工具调用、数据外发或系统提示。导入正文与模型生成HTML均按内容安全规则展示。真实数据接入时，密钥仅在服务端；用户关注列表按授权使用，演示使用构造数据。

## 12. 数据可行性与接入边界

下表是2026-11-19核对官方文档后的设计判断，并非接口实调结果。本轮未获取API Key，未调用扶摇或iFinD金融数据工具。

| 能力 | 官方材料所示 | 本方案处理 |
|---|---|---|
| 标的消歧、行情、交易日历等 | 扶摇项目介绍列出元信息与A股行情/财务等数据域 | 作为后续接入候选，接入前验证授权、字段和错误语义 |
| 资讯事件库 | 文档含event_id、same_events、related_stock等，但明确标注暂未开放外部接入 | 不将该接口当作可用依赖；内部能力接入需另行确认 |
| 公告与新闻内容 | 公告详情页提供基本信息与结构化解读；开发工具概览又明确新闻公告原文、研报原文非公开能力 | 不能据详情页假定取得原文；验证具体账号、入口与内容权限，解读与原文分层 |
| iFinD MCP | 官方页面说明支持行情、财务、公告、宏观等查询 | 当前环境未验证可调用工具、历史覆盖与全文权限；不承诺实时全量抓取 |
| 没有可用金融正文时 | 无法核实原始片段和全部来源覆盖 | 使用明确标识的合成资料验证主链路；真实接入后另行做端到端验收 |

## 13. MVP范围与落地顺序

**P0：先把一个事件看清楚。** 自选/事件入口；链接或文本导入；事件候选合并与撤销；逐句性质标签；同源转载折叠；四时间记录；当前快照与变化时间线；冲突对照；更正/否认/终止/过期/失败处理；证据定位；直接标的关系；历史回放。

**P1：再持续追踪多个事件。** 在权限验证后接入增量更新；实质变化通知；标的关系复核；审核队列；可分享的带时点快照。

**暂缓：** 全市场实时覆盖、自动认定传闻真伪、复杂产业链自动推荐、行情因果归因、交易执行、价格预测。先降低错误合并和无证据结论。

若按附件的24小时条件实施，可按以下顺序切分，前提是开发环境与数据权限已就绪：

| 时段 | 工作与验收点 |
|---|---|
| 0–3小时 | 固定事件/主张/证据模型、合成案例、规则与验收断言 |
| 3–9小时 | 导入→抽取→候选合并→证据快照主链路；先保证单事件闭环 |
| 9–15小时 | 详情、来源侧栏、冲突对照、版本回放与纠错 |
| 15–20小时 | 更正传播、异常降级、边界检查；权限可用时再接1个真实来源 |
| 20–24小时 | 验收、访问验证、部署、README、AI参与记录与测试说明 |

若资料权限未就绪，应交付清晰标识的合成数据版本，并把真实采集列为未完成项。仅有模型摘要和静态截图不足以证明识别、合并、更新主链路已实现。

## 14. 验收与指标

以下为建议目标，不是已有测试成绩。

| 场景 | 必须满足的结果 |
|---|---|
| 一条匿名消息被12次转载 | 来源家族仍为1；不因传播数量升级核验状态 |
| 同公司、同月、两笔交易 | 独立事件；可关联，不能误合并 |
| 公告包含“拟、若、尚需审批” | 条件和阶段保留；不显示已完成 |
| 公司只否认“已签正式合同” | 仅对应主张被标记；不推定从未洽谈 |
| 公告更正10亿元为1亿元 | 当前字段、摘要、派生关系、缓存与通知同步更新；旧版可查 |
| 两个直接来源同口径矛盾 | 双方并列、状态待核实；无静默选边 |
| 昨日公告今日入库 | 披露与抓取分别记录；系统当时视图无未来材料 |
| 正文缺失或只有AI解读 | 缺口显式展示；解读不能作为原始文本 |
| 接口超时、业务失败、空列表 | 显示异常和最后成功检查；不发布新的肯定性快照 |
| 原文撤回或关系依据过期 | 当前支撑与派生推断失效，历史保留 |
| 同一数值的万元/亿元或上限/实际混用 | 先校验单位口径；不生成虚假的数值变化 |
| 外部正文要求执行命令或给买卖建议 | 作为来源内容，不执行指令；输出仍受产品边界约束 |

离线评估采用人工标注的事件、主张、来源家族与演化序列，按事件分割评估，避免同源转载进入训练和测试两边造成虚高。先用合成边界集验证规则，再用经授权的真实材料验证泛化。

上线前硬门槛：验收集中关键主张100%可定位到对应文档版本；所有明确更正、撤回场景的旧依据不得继续支撑现时结论；历史知识视图不得出现未来材料。生产持续监测无证据结论率、错误合并率、遗漏更正率与资料覆盖缺口。

用户验证建议：邀请6–8名目标用户，对照新闻列表完成同一组任务。记录一分钟内正确回答“当前状态、决定性依据、尚未确认点”的完成率，并测量定位原始证据耗时与错误判断。业务观察追踪事件后7日内有实质变化时的回访率；不以交易频率或短期收益作为成功指标。

## 15. 本轮产出与验证范围

本轮完成：产品定位、主链路、信息架构、证据模型、时间与状态规则、关联解释、合成案例、可行性文档核对、MVP与验收设计，以及对话内交互演示。

AI参与：设计初稿、独立的产品评审与状态规则评审、交互演示编写。评审重点纠正了四类容易误导的表述：把否认范围扩大、把框架金额当订单额、把更正当业务缩水、把框架终止当取消所有订单。

演示实际验证：使用本地隔离浏览器检查了金额更正与旧字段标记、历史视图不泄漏未来证据、单一传闻来源、公司否认范围、条件研报、框架终止、关联假设更新、接口超时和超过复核周期。上述交互断言通过，浏览器未出现脚本运行错误。在320、736、1024像素宽度下检查三个视图均无横向溢出，并目视核对桌面与窄屏截图。该验证仅覆盖固定合成案例和前端交互，不证明真实文本抽取、自动聚类、数据采集或后台状态引擎已经实现。

实际金融接口、公开Web部署、代码仓库发布、真实用户研究与真实数据端到端测试均未在本轮完成，不作为既有成果表述。
